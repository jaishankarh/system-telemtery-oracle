# Applications are discovered dynamically, not from a fixed list

A hard-coded list of known programs can never cover everything a developer runs, especially background tools. So grouping falls through layers, first match wins: (1) Containers and Pods by cgroup; (2) built-in App Profiles for programs that need special folding (editor family with its language servers, JetBrains, browsers, Android emulator + Gradle) and Dev & Build per Project; (3) the systemd unit, snap or flatpak the process's cgroup belongs to, which modern desktops create per launched app and per service; (4) the top ancestor below the session or init; (5) Other only when nothing above gives a name. Users can add or rename groups in the config file. Layer 3 relies on systemd cgroup naming, so on non-systemd distros grouping falls back to layer 4.
