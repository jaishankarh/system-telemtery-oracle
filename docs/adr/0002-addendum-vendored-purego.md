# ADR 0002 addendum: NVML is loaded by a vendored copy of purego

The module proxy is unreachable in the build environment, so `github.com/ebitengine/purego` (Apache-2.0, commit 715acd0, Oct 2026) is vendored, trimmed to linux/amd64 and linux/arm64 without cgo, under `internal/third_party/purego` (licence kept). Two local edits: the import path, and `reflect.TypeAssert` (Go 1.25) replaced by a type assertion so it builds on Go 1.24. Only the GPU package imports it, and only when `CGO_ENABLED=0`.

How it works: purego imports libdl/libc through `//go:cgo_import_dynamic` and installs "fakecgo" (the runtime's cgo hooks written in Go and assembly) so C code gets proper thread-local storage. `dlopen("libnvidia-ml.so.1")` and `dlsym` then give NVML function pointers that are called through `SyscallN`. The NVML layer (`internal/gpu`) is defensive: it opens the library only when `/dev/nvidiactl` or `/proc/driver/nvidia` exists, retries a failed load only every ~5 minutes, recovers from panics, and gives up on a call that blocks longer than 1.5 s. Any failure means no NVIDIA data.

Consequence and risk: the binary is no longer fully static. It is a dynamically linked ELF that needs glibc (`libc.so.6`, `libdl.so.2`, `libpthread.so.0`, all present on glibc systems, including old ones). It will not start on musl systems such as Alpine. The ADR's promise "starts on machines without a GPU or driver" holds for glibc machines only. fakecgo depends on Go runtime internals (linkname), so a Go upgrade can break it; the upstream copy must be re-vendored then. Removing the risk means dropping NVIDIA support or shipping a second, cgo-free `-nogpu` build.
